## 한눈에 보는 사용자 주체

- **User**: 조직/테넌트 안에서 **할당된 역할과 권한 범위 내에서 기능을 사용하는 일반 사용자**
- **Admin**: 조직/테넌트 안에서 **사용자·리소스·정책을 관리하는 관리자**
- **Super Admin**: AgenticCP **플랫폼 전체를 관할하는 최상위 관리자**

이 문서는 멀티 테넌트 환경(1 조직 = 1 테넌트)에서 **“누가 어떤 책임과 권한을 가지는지”** 를 명확히 하기 위한 기준을 제공한다.

---

## 공통 전제

- 모든 사용자는 **어느 하나의 조직(=테넌트)에 속해 있다.**
- 실제 권한은 RBAC(Role-Based Access Control)로 세밀하게 제어하지만,  
  이 문서에서는 이해를 위해 **대표적인 책임 범위** 기준으로 구분한다.

---

## User (일반 사용자)

### TL;DR

- 특정 조직/테넌트에 소속되어,  
  **자신에게 부여된 역할 범위 내에서 클라우드 리소스와 기능을 사용하는 기본 사용자**

### 개념 정의

User는 AgenticCP의 **기본 주체**로,  
자신이 속한 조직(=테넌트) 내에서 할당된 권한에 따라 리소스를 조회·생성·변경하는 사용자를 의미한다.

기본적으로 `ROLE_USER` 또는 이에 상응하는 역할을 가지고,  
일상적인 운영 업무(서비스 배포, 모니터링 조회, 일부 설정 변경 등)를 수행한다.

### 책임과 권한 범위

- **책임**
  - 자신에게 허용된 리소스와 기능을 **정책에 맞게 사용하는 것**
  - 개인 계정 보안 유지 (비밀번호 관리, MFA 사용 등)
  - 필요한 경우 Admin에게 권한 요청 또는 이슈 리포트

- **권한 범위 (일반적인 예시)**
  - 자신의 조직(=테넌트)에 속한 리소스만 조회/조작 가능
  - 팀 혹은 개인에게 할당된 프로젝트, 서비스, 대시보드 등을 관리
  - 플랫폼 전역 설정, 다른 조직/테넌트 리소스는 접근 불가

---

## Admin (조직/테넌트 관리자)

### TL;DR

- **하나의 조직(=테넌트) 내에서 사용자와 리소스, 정책을 관리하는 책임을 가진 관리자**

### 개념 정의

Admin은 특정 조직/테넌트 범위 안에서 **운영 책임을 지는 관리자 역할**이다.  
일반 사용자보다 높은 권한을 가지며,  
해당 테넌트의 **사용자, 권한, 일부 보안/비용 정책, 클라우드 계정 설정** 등을 관리한다.

일반적으로 `ROLE_ADMIN` 또는 테넌트 관리자 역할로 표현된다.

!!! info "기본 설정 (Default)"
    **조직을 생성한 사용자는 기본적으로 해당 조직의 Admin 역할을 자동으로 부여받는다.**  
    이는 조직 생성 시점에 자동으로 적용되는 기본 동작이며,  
    이후 Super Admin이 필요에 따라 다른 사용자에게도 Admin 역할을 부여하거나 변경할 수 있다.

### 책임과 권한 범위

- **책임**
  - 조직 내 사용자 라이프사이클 관리
    - 사용자 생성/초대/비활성화
    - 역할 및 권한 부여/회수
  - 조직 단위 리소스와 설정 운영
    - 클라우드 계정/프로바이더 연결 관리
    - 테넌트 수준 보안/비용/기능 플래그 설정 조정
  - 정책 준수 및 감사
    - 조직 내 이상 행위 모니터링
    - 보안/컴플라이언스 요구사항 반영

- **권한 범위 (일반적인 예시)**
  - **스코프**: 자신이 관리하는 단일 조직(=테넌트)
  - **관리 대상**
    - 해당 테넌트의 모든 User 계정
    - 테넌트에 속한 리소스와 일부 정책/설정
  - **제한**
    - 다른 조직/테넌트에는 권한 없음
    - AgenticCP 플랫폼 전역(Global) 설정은 변경 불가

---

## Super Admin (플랫폼 전역 관리자)

### TL;DR

- AgenticCP 전체를 관할하며,  
  **모든 조직/테넌트, 전역 리소스, 플랫폼 설정을 조정할 수 있는 최상위 관리자 역할**

### 개념 정의

Super Admin은 AgenticCP **플랫폼 전반의 운영과 보안, 컴플라이언스를 책임지는 시스템 관리자**이다.  
모든 테넌트와 글로벌 리소스/정책에 접근할 수 있으며,  
주로 인프라/플랫폼 팀, 보안 조직 등 극히 제한된 사람에게만 부여된다.

일반적으로 `ROLE_SUPER_ADMIN` 혹은 이에 준하는 전역 관리자 역할로 표현된다.

### 책임과 권한 범위

- **책임**
  - 전체 테넌트 라이프사이클 관리
    - 테넌트 생성/승인/일시정지/종료
  - 플랫폼 전역 설정 관리
    - 글로벌 보안 정책, 감사 로깅 전략
    - 기능 플래그, 플랫폼 Config, 멀티 클라우드 통합 설정
  - 장애 대응 및 운영 안정성
    - 전역 모니터링, 용량/성능 관리
    - 업그레이드 및 마이그레이션 계획 실행

- **권한 범위 (일반적인 예시)**
  - **스코프**: AgenticCP 전체 (모든 조직/테넌트, 전역 리소스)
  - **관리 대상**
    - 모든 테넌트 및 그 상태
    - 전역 클라우드 프로바이더, 통합 계정, 공용 리소스
    - 플랫폼 전역 보안/설정/비용/모니터링 정책
  - **강화된 통제 필요**
    - MFA, IP 제한, 별도 승인 프로세스 등 강력한 보안 제어 전제를 권장
    - 모든 행동은 **감사 로그(Audit Log)** 로 남겨 추적 가능해야 함

---

## 관계 및 설계 가이드

- **조직(Organization) / 테넌트(Tenant)와의 관계**
  - User와 Admin은 항상 **하나의 조직(=테넌트)에 소속**된다.
  - Super Admin은 플랫폼 전역 역할이지만,  
    구현 상 특정 조직에 소속되더라도 **권한 스코프는 모든 테넌트**에 걸친다.

- **역할 설계시 권장 패턴**
  - 비즈니스/UX 레벨에서는 **“조직 사용자 / 조직 관리자 / 플랫폼 관리자”** 같은 용어를 사용하고,  
    내부 구현에서는 `ROLE_USER`, `ROLE_ADMIN`, `ROLE_SUPER_ADMIN` 등으로 매핑한다.
  - 변경 가능성이 있는 세부 권한(예: “읽기 전용 운영자”)은  
    별도 Role로 세분화하되, 상위 개념(User/Admin/Super Admin)과의 관계를 문서화해 둔다.
